=====================================================================
1. KEPUTUSAN YANG SUDAH DIKONFIRMASI (TIDAK DIASUMSIKAN)
=====================================================================

A. Sikap berbasis kejadian (event-based), bukan penilaian rutin harian.
B. Skala sikap 1-5; 1 = Kurang, 5 = Sangat Baik.
   Normalisasi benefit: R_S = (rata-rata kejadian - 1) / 4.
C. Kehadiran efektif = hadir + izin + sakit. Hanya alpa yang menurunkan
   skor.
D. Bobot SAW = 4:4:5 untuk Akademik:Kehadiran:Sikap, total 13. Backend
   memakai 4/13, 4/13, 5/13; pembulatan dua desimal hanya untuk UI.

3. CONTOH PERHITUNGAN MANUAL (ACUAN UNIT TEST)
=====================================================================

Setting: W_A = 4/13, W_K = 4/13, W_S = 5/13; aman >= 0,67;
perhatian >= 0,34; berisiko < 0,34.

Contoh 1 — semua kriteria lengkap dan baik
  Nilai akademik: 100                -> R_A = 1,00
  Kehadiran: hadir, izin, sakit (3 hari tercatat, 3 hari wajib)
                                     -> R_K = 3/3 = 1,00
  Sikap: satu kejadian nilai 5        -> R_S = (5-1)/4 = 1,00
  Vi = 1*(4/13) + 1*(4/13) + 1*(5/13) = 1,0000 -> Baik / Aman

Contoh 2 — izin/sakit tidak menurunkan skor, alpa menurunkan
  Kehadiran: hadir, izin, sakit, alpa (4 hari wajib)
                                     -> R_K = 3/4 = 0,75
  Sikap: satu kejadian nilai 3        -> R_S = (3-1)/4 = 0,50
  Akademik: rata-rata 85              -> R_A = 0,85
  Vi = 0,85*(4/13) + 0,75*(4/13) + 0,50*(5/13)
     = 8,9/13 = 0,6846 -> Baik / Aman

Contoh 3 — tanpa catatan sikap
  Akademik 90, kehadiran lengkap, sikap tidak ada
  -> kategori Data Belum Lengkap, skor = null (BUKAN Berisiko)

Contoh 4 — sebagian hari sekolah belum dicatat
  3 catatan kehadiran untuk siswa, tetapi 4 tanggal tercatat di kelas
  -> kategori Data Belum Lengkap, skor = null

Contoh 5 — siswa ABK
  -> kategori ABK, skor = null, tidak digabung dengan Data Belum Lengkap

=====================================================================
4. CATATAN IMPLEMENTASI / MIGRASI
=====================================================================

- Kolom `sikap.nilai` sudah INTEGER tanpa constraint 1-4, sehingga skala
  1-5 tidak memerlukan perubahan skema. Validasi ada di Zod dan controller.
- Unique index `kehadiran(siswaId, tanggal)` sudah dipasang oleh migrasi
  hardening sebelumnya, sehingga pengiriman ulang tidak membuat baris ganda.
- Migrasi 20261125000000-tahap-1-saw.cjs menyamakan bobot pada baris
  setting_spk yang sudah ada ke rasio presisi 4/13, 4/13, 5/13.
- Duplikasi kejadian sikap dicegah di aplikasi dengan kunci
  (siswaId, jenis, nilai, catatan, tanggal, tahunAjaranId).
- Status baru "Data Belum Lengkap" memakai kode `data_belum_lengkap`
  dan tersedia pada StatusBadge, rekap kelas/kepsek, filter, serta laporan.

Pengujian yang dijalankan setelah perubahan:
  npm test --prefix server
  npm run lint --prefix server
  npm test --prefix client
  npm run lint --prefix client
  npm run build --prefix client

Belum dijalankan: Black Box, UAT, dan perbandingan manual dengan sistem
lama (sesuai batas spesifikasi Tahap 1).
