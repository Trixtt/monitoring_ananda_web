KEPUTUSAN FINAL IMPLEMENTASI TAHAP 1
MONITORING ANANDA — SD NEGERI 4 KELING

Dokumen ini menggantikan catatan asumsi konservatif pada versi sebelumnya.
Semua poin di bawah sudah diputuskan dan dipakai sebagai perilaku final sistem.
Tidak ada fitur baru di luar keputusan ini yang ditambahkan.

=====================================================================
1. KEPUTUSAN YANG SUDAH DIKONFIRMASI SEBELUMNYA
=====================================================================

A. Sikap berbasis catatan kejadian (event-based), bukan penilaian rutin harian.
B. Revisi v1.1 menggantikan skala 1-5 dengan nilai dasar 100. Setiap catatan
   memiliki pengurangan; nilaiSikap = max(0, 100 - totalPengurangan) dan
   R_S = nilaiSikap / 100. Tanpa catatan berarti tidak ada pengurangan, bukan
   predikat "Sangat Baik". Angka pengurangan masih konfigurasi teknis awal,
   bukan kutipan keputusan kepala sekolah.
C. Kehadiran efektif = hadir + izin + sakit. Hanya alpa yang menurunkan
   skor.
D. Bobot SAW = 4:4:5 untuk Akademik:Kehadiran:Sikap, total 13. Backend
   memakai 4/13, 4/13, 5/13; pembulatan dua desimal hanya untuk UI.
E. Pengurangan seluruh catatan dijumlahkan; aspek sosial dan spiritual hanya
   informasi pendukung pada catatan, bukan dua nilai yang dirata-rata.
F. Bobot, interval klasifikasi, dan ambang rekomendasi dapat diubah admin.

4. CONTOH PERHITUNGAN MANUAL (ACUAN UNIT TEST)
=====================================================================

Setting: W_A = 4/13, W_K = 4/13, W_S = 5/13; aman >= 0,67;
perhatian >= 0,34; berisiko < 0,34.

Contoh 1 — semua kriteria lengkap tanpa catatan negatif
  Nilai akademik: 100                  -> R_A = 1,00
  Kehadiran: hadir, izin, sakit (3 tanggal tercatat)
                                       -> R_K = 3/3 = 1,00
  Sikap: tidak ada catatan             -> nilaiSikap = 100; R_S = 1,00
  Vi = 1*(4/13) + 1*(4/13) + 1*(5/13) = 1,0000 -> Baik / Aman

Contoh 2 — izin/sakit tidak menurunkan skor, alpa dan catatan menurunkan
  Kehadiran: hadir, izin, sakit, alpa (4 tanggal tercatat)
                                       -> R_K = 3/4 = 0,75
  Sikap: satu catatan "Tidak mengerjakan tugas" (pengurangan 5)
                                       -> nilaiSikap = 95; R_S = 0,95
  Akademik: rata-rata 85               -> R_A = 0,85
  Vi = 0,85*(4/13) + 0,75*(4/13) + 0,95*(5/13)
     = 11,15/13 = 0,8577 -> Baik / Aman

Contoh 3 — tanpa catatan sikap (KEPUTUSAN BARU)
  Akademik 90, kehadiran lengkap, tidak ada catatan sikap
  -> nilaiSikap = 100 (R_S = 1,00); skor dihitung final; bukan Data Belum
     Lengkap dan bukan predikat "Sangat Baik".

Contoh 4 — sebagian tanggal kehadiran belum dicatat
  3 catatan kehadiran untuk siswa, tetapi 4 tanggal tercatat di kelas
  -> kategori Data Belum Lengkap, skor = null.

Contoh 5 — siswa ABK
  -> kategori ABK, skor = null, tidak digabung dengan Data Belum Lengkap.

Contoh 6 — ambang dapat diatur
  Jika ambang akademik diubah ke 0,80 dan R_A = 0,70, maka rekomendasi
  akademik tetap muncul walaupun nilai tersebut memenuhi ambang bawaan 0,65.

Contoh 7 — agregasi per mapel dan rulebase
  IPA: 80 dan 90 -> rata 85 (dua catatan tetap dihitung sekali).
  Matematika: 60 -> rata 60.
  R_A = ((85 + 60) / 2) / 100 = 0,725.
  IPA mencapai ambang unggul 85 -> rekomendasi pengayaan.
  Matematika di bawah KKM 70 -> rekomendasi bimbingan tambahan.

5. CATATAN IMPLEMENTASI / MIGRASI
=====================================================================

- Kolom `tahun_ajaran` baru: semesterAktif, ganjilMulai, ganjilAkhir,
  genapMulai, genapAkhir. Nilai awal 2025/2026 diisi migrasi dan seed.
- Kolom `setting_spk` baru: ambangAkademik, ambangSikap, ambangKehadiran,
  kkmMapel (70), dan ambangUnggul (85).
- Migrasi baru: 20261125130000-semester-dan-ambang.cjs,
  20261126000000-kkm-dan-ambang-unggul.cjs, dan
  20261128000000-catatan-kejadian-sikap.cjs. Migrasi Tahap 1 sebelumnya
  (20261125000000-tahap-1-saw.cjs) sudah diterapkan dan tidak dijalankan ulang.
- `hitungSkorData()` menerima `nilaiRows` (baris nilai dengan relasi mapel)
  dan `sikapCatatan` (catatan kejadian), bukan lagi `nilaiAngka`/`sikapAngka`.
- Kolom `sikap.nilai` dihapus. Kolom baru: `kategori`, `pengurangan`,
  `guruId`, dan `kehadiranId`. `pengurangan` adalah snapshot dari
  `server/src/config/sikap.js` saat catatan disimpan.
- Duplikasi catatan sikap dicegah di aplikasi dengan kunci
  (siswaId, kategori, jenis, catatan, tanggal, tahunAjaranId, kehadiranId)
  dan di database dengan index unik `kehadiranId` untuk Bolos.
- Status "Data Belum Lengkap" memakai kode `data_belum_lengkap`.
- Migration revisi v1.1 sudah dijalankan setelah backup:
  `server/backups/monitoring_siswa_20261128_144338.sql` dengan SHA-256
  `c806f8ac37663a460ba3f78aaffffee06ef73a10210761a3c56d15f31dde4c71`.
  Cabang `down` hanya mengembalikan struktur lama; baris demo yang dihapus
  tidak dipulihkan tanpa backup. Backup tidak di-commit.

Pengujian otomatis revisi v1.1 sudah dijalankan dengan hasil:
  npm test --prefix server       -> 77 test lulus, 0 gagal
  npm run lint --prefix server   -> bersih
  npm test --prefix client       -> 11 test lulus, 0 gagal
  npm run lint --prefix client   -> bersih
  npm run build --prefix client  -> berhasil

Seed dijalankan tanpa `SEED_FORCE=true` dan dilewati karena data demo sudah
ada; baris sikap demo yang dihapus migrasi belum terisi ulang.

Tidak dijalankan: UAT/Black Box dan pengujian manual oleh pengguna untuk
revisi ini. Keduanya memerlukan izin eksplisit pengguna terlebih dahulu.
